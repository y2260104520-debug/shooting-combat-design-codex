# General Cases

这里保存通用游戏设计中的高价值案例。

## 什么时候写入

只记录满足至少一项的内容：
- 一次真实方案评审得出了明确判断
- 某个边界问题实际导致返工
- 某种设计选择产生了可复用经验
- 用户明确要求沉淀

不要把普通聊天直接复制进来。

## 推荐结构

- Context
- Goal
- Phenomenon
- Hypothesis
- Analysis
- Decision
- Result
- Candidate Rule
- Status

Status 建议：
- observation
- candidate
- validated
- rejected

## 方法论升级

案例中的 Candidate Rule 不自动进入 methodology/。

只有用户明确确认后，才整理为 Confirmed Rule 并写入 methodology/common/。
