# PUBGM僵尸模式｜策划文档需求规范

根据之前的文档修改和评审要求，整理成一套后续可以直接沿用的标准。主要分为内容要求、结构要求、文本要求和格式要求。

## 一、内容要求

### 1. 设计依据与范围

- 以甲方提供的需求图片、项目现有方案和已确认规则为依据。
- 明确区分 PUBG 主模式继承内容与僵尸模式新增适配内容。
- 主模式已有功能需要明确写出保留哪些内容，不能只写一句「沿用主模式」。
- 只展开当前需求明确涉及的功能，不主动增加其他系统或机制。
- 不写没有实际意义的功能说明，也不为了让文档显得完整而增加条目。

### 2. 规则继承

对于主模式已有功能，明确具体保留内容。

例如：

| 功能 | 需要明确的内容 |
|--------|--------|
| 视角 | 第三人称视角 |
| 瞄准与开镜 | 肩射、开镜及对应状态切换 |
| 移动 | 跑、蹲、趴、跳、翻越等动作 |
| 枪械操作 | 原有枪械操作及手感 |
| 玩家交互 | 原有玩家与场景、玩家与玩家交互规则 |

对于新增适配，写清楚具体变化及作用。

### 3. 功能规则

功能描述需要达到策划、程序、美术和测试能够理解的程度。

尤其是受击提示、怪物威胁预警、精英怪攻击范围提示等细节功能，需要明确：

- 触发条件
- 表现方式
- 更新规则
- 解除条件
- 多目标同时出现时的处理方式

不要求所有功能机械地使用同一套结构，根据功能复杂程度拆分。

### 4. 当前3C文档的特殊要求

以下属于已经确定的设计约束：

| 模块 | 已确认要求 |
|--------|--------|
| 威胁预警 | 初版只根据怪物距离判断，使用R1、R2两级预警 |
| 威胁预警 | 不使用预计攻击时间判断 |
| 威胁预警 | 升级立即触发，降级与解除增加保持时间 |
| 预警距离 | 玩家与怪物碰撞体中心点之间的三维直线距离 |
| 攻击数量限制 | 名额释放后重新判断，距离近的优先获得 |
| 精英怪范围提示 | 默认锁定预警区域，追踪型攻击单独说明 |
| 交互优先级 | 继承主模式规则，保留场景自动判断 |
| 战斗状态区 | 展示武器品质和元素效果 |
| 操作入口 | 战术道具次数、大招充能放在各自操作入口 |

另外，近身轮廓与威胁预警存在信息重复的可能，需要明确各自职责。

## 二、文档结构要求

整体采用清晰的分级结构。

| 层级 | 内容 | 要求 |
|--------|--------|--------|
| 文档版本 | 版本记录、修改说明 | 简洁记录版本变化 |
| 整体设计 | 设计目的 | 全文只保留一个，放在文档顶部 |
| 功能章节 | 功能模块划分 | 按实际功能组织 |
| 详细规则 | 功能说明、触发条件、表现、规则等 | 复杂功能细化条目 |
| 示意图 | 插图、流程图、布局图 | 提前预留位置 |
| 配置参数 | 参数名称、当前值、单位、说明 | 独立整理 |

**重点：**

- 设计目的只写一个，不在每个章节重复写。
- 功能模块与具体规则之间要有明确层级。
- 复杂功能不能只用一段概括性描述。
- 需要插图的地方提前留出插图位置，并注明图片需要表达的内容。
- 流程图、布局示意图、规则示意图分别处理。

## 三、文本描述要求

(重点要求)

### 1. 策划视角

描述以玩家行为和功能表现为核心。

| 不推荐 | 推荐 |
|--------|--------|
| 根据当前逻辑进行优先级判定 | 根据当前场景自动判断优先交互对象 |
| 维护攻击状态及名额 | 攻击结束或被打断后释放攻击名额 |
| 进行相关状态更新 | 根据怪物距离变化更新预警等级 |
| 保持数据一致性 | 界面提示与实际交互对象保持一致 |

### 2. 文本风格

- 简洁、直接、明确。
- 尽量使用自然的策划语言。
- 减少程序实现术语，例如「口径」「状态维护」「数据同步」等。
- 不使用过多抽象描述。
- 不重复解释同一条规则。
- 不写无意义的限制性描述和排除项。
- 不写「不做什么」「不增加什么」等与实际功能无关的内容。

### 3. 参数要求

只保留实际有意义的配置项。

参数表统一使用：

| 参数项 | 当前值 | 单位 | 说明 |
|--------|--------|--------|--------|
| 一级预警距离 | 待配置 | cm | 一级预警触发距离 |
| 二级预警距离 | 待配置 | cm | 二级预警触发距离 |
| 预警降级/解除保持时间 | 待验证 | 秒 | 降级或解除前的保持时间 |

未知参数明确标注待确认或待实机验证，不随意填写默认数值。

## 四、Excel格式要求

| 项目 | 要求 |
|--------|--------|
| 样式 | 参考用户提供的原始策划案格式 |
| 分页 | 按文档版本、功能规则等内容合理划分 |
| 单元格合并 | 取消合并单元格 |
| 行高 | 使用默认值 |
| 列宽 | 使用默认值 |
| 空行 | 清理无意义的空行 |
| 文本 | 避免内容被压缩、遮挡或截断 |
| 单元格 | 保持内容与标题对应，不错位 |
| 参数表 | 每个参数独占一行 |
| 插图区域 | 保留明确的插图占位说明 |

特别注意：单元格宽高使用默认值，不通过随意拉伸行列来解决排版问题。内容过长时优先精简或拆分条目。

## 五、交付前检查

每次修改文档后，需要检查：

- [ ] 是否完整覆盖甲方提出的功能。
- [ ] 是否明确写出主模式需要保留的内容。
- [ ] 是否存在规则缺失或前后冲突。
- [ ] 是否有重复、冗余或没有意义的描述。
- [ ] 是否存在过于程序化的文本。
- [ ] 复杂功能是否拆分清楚。
- [ ] 是否缺少必要的插图、流程图和示意图预留。
- [ ] 参数是否与对应功能规则一致。
- [ ] 是否存在空行、错位、单元格压缩和文本截断。
- [ ] 是否保持参考文档的格式。
- [ ] 版本记录是否同步更新。

## 六、最重要的原则

后续整理文档时，优先遵循以下四条：

1. **保留原有规则**：在现有主模式基础上明确继承与适配，不随意改变原有设计。
2. **内容有实际意义**：只写当前功能需要的内容，不为完整性增加无用条目。
3. **规则清楚可执行**：复杂功能拆开描述，让程序、美术、测试能够直接理解。
4. **文档简洁规范**：结构清晰、文本自然、格式统一，必要的示意图提前预留。

这套规范后续可以作为 PUBGM 僵尸模式策划案的通用整理标准。不同类型的文档再根据实际功能调整细节，不必强行套用同一套章节结构。

## 七、格式母版补充约束

本规范仅适用于 PUBGM 僵尸模式，不应用于其他项目。原始 Excel 为格式母版，禁止自行重新设计版式。格式母版约束优先于一般排版建议。

母版：《PUBGM_战斗专精_功能策划案_V0.9.xlsx》《PUBGM_战斗专精_策划案_原稿格式版.xlsx》《首版枪械与配件功能-普通配件方案111(3).xlsx》。

- 文档形态为文字型策划案。
- 一级章节黑底白字、14号加粗；二级标题11号普通文字。
- 规则标题与正文分行，详细规则按功能层级展开。
- 参数配置使用独立表格，插图使用独立预留区域。
- 取消合并，少量使用边框，避免密集网格；行高列宽使用默认值。
- 保留母版字体、颜色、留白、层级和视觉习惯。
- 制作前核对工作表结构及标题行、正文行、参数表关系；交付前对照母版检查实际文件。缺少母版时明确记录，不能声称已完成一致性验证。
