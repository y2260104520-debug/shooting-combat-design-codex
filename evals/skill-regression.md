# Skill Regression

目的：每次调整 Skill 或 Methodology 后，用固定真实风格问题做回归，检查 AI 有没有偏离预期工作方式。

不要求答案完全一致，只检查“判断链路”和“关键行为”。

---

## E01｜用户直接给调参方案

### 输入
AR 中距离太强，我想直接加垂直后坐。

### 必须做到
- 不直接接受“加后坐”。
- 先区分理论 TTK、eTTK、命中率、距离覆盖、支付成本。
- 判断是否可能是结构性泛用。
- 最后再决定后坐是否是正确干预点。
- 给至少一个可验证指标。

### 不应出现
- 一上来直接给 +10% / +20% 后坐。
- 只谈理论 TTK。

---

## E02｜通用系统规则检查

### 输入
帮我检查这个随机事件系统有没有问题。

### 必须做到
- 先看目标与规则是否成立。
- 检查触发、重复、上限、无合法候选、冲突和结束条件。
- 只指出问题和最小修改。

### 不应出现
- 主动新增大量事件类型。
- 把“丰富内容”当成主要建议。

---

## E03｜用户把现象当根因

### 输入
玩家总拿某个英雄，说明这个英雄伤害太高。

### 必须做到
- 指出“高选择率 ≠ 已证明伤害过高”。
- 至少考虑强度、泛用性、易用性、场景适配、阵容需求等原因。
- 给区分原因的验证方式。

### 不应出现
- 直接建议削伤害。

---

## E04｜技能是否侵蚀枪械

### 输入
做一个技能，按下后自动锁敌并连续射击 2 秒。

### 必须做到
- 先判断技能解决什么压力。
- 检查是否直接替代瞄准和枪械兑现。
- 检查高低端收益差异和反制。
- 如目标成立，优先考虑“创造条件”而不是直接替代射击。

### 不应出现
- 只设计特效、伤害和 CD。

---

## E05｜3C 问题归因

### 输入
移动速度数值没问题，但角色跑起来很飘。

### 必须做到
- 优先检查 Character 层的加速度、制动、转向、重力和状态切换。
- 不把最大速度当唯一指标。
- 给隔离验证方法。

### 不应出现
- 直接建议降低最大移动速度。

---

## E06｜镜头控制权竞争

### 输入
后坐回正时准星会突然往下抢一下。

### 必须做到
- 检查玩家输入、后坐增量、系统回正、镜头插值的叠加顺序。
- 明确这可能是控制权竞争，不只是“回正速度太快”。
- 建议隔离系统回正测试。

### 不应出现
- 只建议把恢复速度调慢。

---

## E07｜已有方案最小修改

### 输入
这套天赋树基本已经定了，帮我看第 4 条反馈怎么改。

### 必须做到
- 保持既有目标与结构。
- 只处理第 4 条。
- 如果需要大改，先证明原结构无法满足。

### 不应出现
- 顺手重做整棵天赋树。

---

## E08｜方法论沉淀边界

### 输入
这次讨论里发现“泛用性本身也是强度”，把它记住。

### 必须做到
- 可以提议形成 Candidate Rule。
- 写明适用条件或边界。
- 用户明确要求“记住/沉淀”后才写入 case 或 methodology。
- 若已有正式规则，优先查重，不重复制造规则。

### 不应出现
- 未确认就自动重写整个 methodology。
