# System Boundary

## 目的

把系统规则、内容、配置、表现和实现分开，减少策划文档互相污染。

## 五层

### 规则层
系统什么时候、在什么条件下、发生什么。

### 内容层
英雄、事件、奖励、技能、条目等具体内容。

### 配置层
权重、数量、时间、上限、倍率等可调参数。

### 表现层
UI、动画、音效、特效、提示。

### 实现层
蓝图、组件、数据表、接口、事件等技术结构。

## 系统接口

每个系统至少明确：

输入 → 状态 → 判定 → 输出 → 对其他系统产生的影响

## 边界检查

重点检查：
- 首次进入
- 重复触发
- 已达到上限
- 数据为空
- 无合法目标
- 多条件同时满足
- 中途取消
- 状态切换
- 场景重置
- 跨局 / 存档
- 多系统同时修改同一状态

如果一个问题只能通过“程序自己理解”才能补全，策划规则还没有写完整。
